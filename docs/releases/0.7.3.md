This patch release makes the **Zotero (Better BibTeX)** database load again with Zotero 10, and fills in the authors of Zotero presentations. It also adds a quality gate that keeps new code in `src/` small and tested.

## 🐛 Bug Fixes

- **Zotero (Better BibTeX) loads with Zotero 10** ([#97](https://github.com/akhmialeuski/obsidian-citation-extended/issues/97)). Zotero 10 closes, without a response, any request whose user agent looks like a browser, as Obsidian's does, unless the request carries the `Zotero-Allowed-Request` header. The database failed to load and **Test connection** failed with `net::ERR_EMPTY_RESPONSE`. The Better BibTeX client now sends the header with the library export, the connection probe and the PDF annotation requests. Older Zotero versions behave as before. Thanks to @Emeriken for the report and the pointer to the fix.
- **Presenters of Zotero presentations become authors** ([#96](https://github.com/akhmialeuski/obsidian-citation-extended/pull/96)). Zotero stores the creators of a presentation as presenters, so a presentation loaded from a **Zotero (local API)** database had no authors, and `{{entry.author}}` was empty in its literature note. Presenters now fill the authors when the item has no CSL authors, and existing authors are kept. Thanks to @johntruckenbrodt for the fix.

## 🔧 Under the Hood

- **A CRAP and size gate for `src/`** ([#98](https://github.com/akhmialeuski/obsidian-citation-extended/pull/98), [#100](https://github.com/akhmialeuski/obsidian-citation-extended/pull/100)). ESLint now limits functions in `src/` to a complexity of 8, 5 parameters and 50 lines, and files to 500 lines, with today's violations recorded in `eslint-suppressions.json` so they can only shrink. `npm run crap-gate`, run before a pull request, scores every function by complexity and test coverage and fails when a function over the threshold is new or got worse than `crap-baseline.json` records.
- The test suite has 1,878 tests across 100 suites, all passing.
