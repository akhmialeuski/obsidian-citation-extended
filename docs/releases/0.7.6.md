This patch release makes a **Zotero (local API)** database sync only what changed since the last sync, and stops the parse warning notice from reappearing after every reload of a database whose warnings never change.

## ✨ New Features

- **Incremental sync for Zotero (local API)** ([#104](https://github.com/akhmialeuski/obsidian-citation-extended/pull/104)). On Zotero 10 and newer, a whole personal or group library no longer downloads every item when it changes. A normal sync asks Zotero for the items, attachments and enabled annotations changed since the last successful sync, reuses the unchanged records from the cache, and uses Zotero's ordered key lists to detect deletions and keep the order. An unchanged library version skips record retrieval entirely. **Sync now** and automatic polling sync incrementally, and **Refresh citation database** still forces a full fetch. Zotero 7 to 9 and collection-scoped sources keep using full fetches. The offline cache moves to a new format that records the API endpoint and the Zotero server identity, an older cache stays usable offline, and the first successful full fetch upgrades it. Thanks to @johntruckenbrodt for the feature.

## 🐛 Bug Fixes & Improvements

- **The parse warning notice appears only for a new warning** ([#103](https://github.com/akhmialeuski/obsidian-citation-extended/issues/103), [#105](https://github.com/akhmialeuski/obsidian-citation-extended/pull/105)). A BibLaTeX database with permanent parse warnings, such as custom macros, showed the same notice after every reload. A load now shows the notice only when it brings a warning the previous successful load did not have, and names the first such warning on the notice's second line. A database that fails while others load, a Readwise outage served from the cache and a failed Zotero annotation fetch still show a notice when they first appear and again when they return after a clean load. Thanks to @cmiramon for the report.
- **The status bar shows the parse warning count** ([#105](https://github.com/akhmialeuski/obsidian-citation-extended/pull/105)). After a load with warnings it reads `Citations: 1234 entries, 57 parse warnings`, and the count disappears once the database loads cleanly.
- **Warnings are counted in full and called warnings** ([#105](https://github.com/akhmialeuski/obsidian-citation-extended/pull/105)). The library kept only the first 10 messages, so the notice, the status bar and the Readwise **Sync now** notice reported at most 10. They now report the true number, and say "parse warnings" instead of "entries skipped", because most warnings do not skip an entry.
