This release adds a command that rewrites one part of a literature note from a template, and lets the references sidebar jump to a citation inside the note. It also fixes two bugs that made the plugin create duplicate notes and re-download the whole library on every reload.

## ✨ New Features

- **Insert or replace with template output** ([#93](https://github.com/akhmialeuski/obsidian-citation-extended/issues/93)). A new command, `Citation Extended: Insert or replace with template output`, is available in the Command Palette and in the editor context menu on a selection. It covers the case of a PDF added in Zotero after the note was created. Select the outdated text, or place the cursor where the new lines should go, and the dialog previews the template output as a line diff before **Apply** writes it. **Extract** finds the part of your content template that produced the selection and loads it into the dialog. Reusable templates are kept in the new **Fragment profiles** settings section. See the [use case](https://github.com/akhmialeuski/obsidian-citation-extended/blob/master/docs/use-cases/replace-selection-with-template.md).
- **Jump to a citation from the references sidebar** ([#88](https://github.com/akhmialeuski/obsidian-citation-extended/issues/88)). A plain click still opens the literature note. **Cmd-click** on macOS or **Ctrl-click** elsewhere selects that citekey in the note and scrolls it into view. Repeated clicks on the same entry walk through every occurrence and wrap after the last, with a `Citation 2 of 3` notice. Citekeys missing from the library can be found the same way, which helps to track down a typo.

## 🐛 Bug Fixes

- **A moved literature note is found again** ([#86](https://github.com/akhmialeuski/obsidian-citation-extended/issues/86)). A note moved out of the literature note folder was never found by the vault-wide search, so every click created a duplicate. Keeping literature notes at the vault root failed in the same way. Both lookups now treat every spelling of the vault root as the whole vault.
- **Offline caches and sync baselines are read back** ([#87](https://github.com/akhmialeuski/obsidian-citation-extended/issues/87)). The plugin wrote its files through the vault adapter and read them through a desktop helper that expects an absolute path, so every read failed silently. As a result each reload fetched the whole Zotero or Readwise library again, and `note-baselines.json` was lost between sessions. Reads now use the same vault-relative path as writes, which also works on mobile.

## 📚 Documentation

- Every screenshot was re-rendered from the current plugin, and five new ones cover the Zotero and Readwise database cards, the references sidebar and inline autocomplete.
- The settings, command and data source pages were corrected where they described behaviour the plugin does not have, such as a "Last wins" merge strategy for duplicate citekeys. Commands are listed under the `Citation Extended:` prefix, and the hotkey tables list all 12 commands.

## 🔧 Under the Hood

- `IFileSystem` now documents that its paths are vault-relative, and its unused `createFolder` was removed. `IVaultAccess.createFolder` stays the only way to create a folder.
- The test double for `normalizePath` now behaves like Obsidian's own, which is the gap that let the folder lookup bug through.
- The test suite has 1,861 tests across 99 suites, all passing.
